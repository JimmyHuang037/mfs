## 需求文件标准模板

每个需求文件必须包含以下结构：

```markdown
---
id: 编号
title: 标题
status: active | done | cancelled | planned
created: YYYY-MM-DD
updated: YYYY-MM-DD
---

# 标题

## 概述
一句话说清楚这个需求要做什么。

## 用户角色
谁用这个功能？

## 功能点
- [ ] 功能 1
- [ ] 功能 2
- [ ] 功能 3

## 数据库变更
需要新建/修改哪些表？

## API 接口
需要新增/修改哪些接口？

## 前端页面
需要新增/修改哪些页面？

## 不做（明确排除）
- 这次不做的东西

## 变更记录
| 日期 | 改了什么 | 为什么 |
|------|---------|--------|
| 2026-07-05 | 初始版本 | — |
```

### 规则

- **功能点用 checkbox** — 做完一个勾一个，AI 能直接看进度
- **变更记录必须写** — 每次改需求都在最后追加一行
- **不要删文件** — 不做的需求改 status 为 `cancelled`，保留历史
- **编号不复用** — 取消的编号不再给新需求用
