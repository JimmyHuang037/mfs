# 需求文档标准

> 所有需求必须按本标准编写，确保 AI 能读懂、能追踪、能执行。

## 1. 文件管理

### 存放位置

```
docs/requirements/
├── README.md                    # 需求索引（自动维护）
├── 001-student-mgmt-system.md   # 第一个需求
├── 002-teacher-score-mgmt.md    # 第二个需求
└── ...
```

### 命名规则

```
三位编号-简短英文标题.md
```

| 正确 ✅ | 错误 ❌ |
|---------|---------|
| `001-student-mgmt-system.md` | `student-system.md`（没编号） |
| `002-teacher-score-mgmt.md` | `02-teacher.md`（编号不够三位） |
| `003-excel-import.md` | `Excel_Import.md`（大写+下划线） |

### 编号规则

- 从 `001` 开始，递增
- 取消的需求**保留文件**，不改编号，status 改为 `cancelled`
- 编号**不复用** — 取消的编号不再给新需求

## 2. 文件结构（必须包含）

每个需求文件必须包含以下部分，顺序固定：

```markdown
---
id: 001
title: 需求标题
status: active | done | cancelled | planned
created: 2026-07-05
updated: 2026-07-05
---

# 需求标题

## 概述
一句话说清楚做什么、给谁用。

## 用户角色
谁用这个功能？用表格列出。

## 功能点
用 checkbox 列出所有功能，做完一个勾一个：
- [ ] 功能 1
- [ ] 功能 2

## 数据库变更
需要新建/修改哪些表？用表格列出字段。
如果没有数据库变更，写"无"。

## API 接口
需要新增/修改哪些接口？用表格列出方法、路径、描述、权限。
如果没有 API 变更，写"无"。

## 前端页面
需要新增/修改哪些页面？用表格列出路由和描述。
如果没有前端变更，写"无"。

## 不做（明确排除）
明确列出这次不做的东西，防止范围蔓延。

## 变更记录
| 日期 | 改了什么 | 为什么 |
|------|---------|--------|
| YYYY-MM-DD | 初始版本 | — |
```

## 3. 状态说明

| 状态 | 图标 | 含义 |
|------|------|------|
| `planned` | ⚪ | 计划中，还没开始做 |
| `active` | 🟡 | 正在做，还没完成 |
| `done` | 🟢 | 做完了，代码已合并 |
| `cancelled` | 🔴 | 不做了，保留文件记录历史 |

### 状态变更规则

- `planned` → `active`：开始做这个需求
- `active` → `done`：所有功能点 checkbox 都勾了
- `active` → `cancelled`：决定不做了
- `done` → `active`：发现遗漏，需要补充

## 4. 功能点写法

### 格式

```markdown
### 分类名称（如：认证、学生管理）
- [ ] 动词 + 对象 + 预期结果
```

### 例子

```markdown
### 认证
- [ ] 学生用学号+密码登录，成功后跳转到成绩页
- [ ] 老师用用户名+密码登录，成功后跳转到成绩管理页
- [ ] 管理员用用户名+密码登录，成功后跳转到学生管理页

### 学生管理
- [ ] 管理员查看所有学生列表，支持分页
- [ ] 管理员新增学生，学号不能重复
- [ ] 管理员删除学生，需要二次确认
```

### 规则

- 每个功能点必须**可验证** — 能写出对应的测试用例
- 用**动词开头** — "查看..."、"新增..."、"删除..."
- 写清楚**预期结果** — 不只是"做什么"，还有"做完后怎样"
- 按**模块分组** — 用 `###` 子标题分类

## 5. 数据库变更写法

### 新表

```markdown
### admins 表（新建）
| 字段 | 类型 | 约束 | 说明 |
|------|------|------|------|
| id | INT | 主键，自增 | |
| username | VARCHAR(50) | 唯一，非空 | 登录用 |
| password | VARCHAR(100) | 非空 | 明文存储 |
```

### 修改现有表

```markdown
### teachers 表（修改）
新增字段：
| 字段 | 类型 | 约束 | 说明 |
|------|------|------|------|
| username | VARCHAR(50) | 非空，唯一 | 登录用，新增 |
| password | VARCHAR(100) | 非空 | 登录用，新增 |
```

## 6. API 接口写法

```markdown
| 方法 | 路径 | 描述 | 权限 |
|------|------|------|------|
| POST | `/api/auth/login/student` | 学生登录 | 公开 |
| GET | `/api/students` | 获取所有学生 | 管理员 |
| POST | `/api/students` | 新增学生 | 管理员 |
```

### 规则

- 路径用 RESTful 风格
- 权限写清楚：公开 / 学生 / 老师 / 管理员
- 一个接口一行

## 7. 变更记录

每次修改需求文件，必须在变更记录追加一行：

```markdown
## 变更记录
| 日期 | 改了什么 | 为什么 |
|------|---------|--------|
| 2026-07-05 | 初始版本 | — |
| 2026-07-06 | 新增 Excel 导入功能点 | 用户要求支持批量导入 |
| 2026-07-08 | 删除路由守卫功能点 | 推迟到 005 需求 |
```

### 规则

- **必须写** — 每次改文件都要追加
- 写**改了什么**和**为什么**
- 日期用 `YYYY-MM-DD` 格式
- 最新的在最下面

## 8. 索引维护

`docs/requirements/README.md` 是需求索引，新增/修改需求时必须更新：

```markdown
| 编号 | 标题 | 状态 | 更新日期 |
|------|------|------|----------|
| 001 | 学生管理系统基础功能 | 🟡 进行中 | 2026-07-05 |
| 002 | 老师成绩管理 | ⚪ 计划中 | — |
```

## 9. AI 使用规则

AI 在开始做需求之前，必须：

1. **读需求文件** — 确认要做什么、不做什么
2. **检查 checkbox** — 看哪些做完了、哪些没做
3. **做完后勾 checkbox** — 更新需求文件
4. **写变更记录** — 记录做了什么改动
5. **更新索引** — 如果状态变了，更新 README.md
