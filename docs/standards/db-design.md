# 数据库设计标准

> 所有数据库设计文档必须按本标准编写，确保 AI 能读懂结构、关系和变更历史。

## 1. 文件管理

### 位置

项目数据库设计文档放在 `docs/db-design.md`。

### 更新时机

- 新建表、改表结构、加索引 → **先改文档，再写 SQL**
- 新增需求涉及数据库变更 → 同步更新设计文档
- 发现设计问题 → 记录到「已知问题」

## 2. 文档结构（必须包含）

按以下顺序组织，每个部分都不能少：

```markdown
# 数据库设计文档

> 数据库: `库名` | MySQL 版本 | 字符集

## ER 关系图
用文字版或 ASCII 画出表关系。

## 现有表
每张表一个子章节，用表格列出字段。

## 待新建/修改的表
标注哪些字段是「待加」的。

## 表关系总结
用 ASCII 图展示完整关系。

## 已知问题
表格列出问题、影响、计划。

## SQL 变更脚本
按执行顺序列出 DDL。

## 变更记录
每次改动追加一行。
```

## 3. 表结构写法

每张表必须包含以下信息：

```markdown
### 表名

> 一句话说明这张表存什么

| 字段 | 类型 | 约束 | 说明 |
|------|------|------|------|
| id | INT | 主键，自增 | 内部 ID |
| name | VARCHAR(100) | 非空 | 名称 |

**现有数据**: 大概多少条
**索引**:
- PRIMARY KEY (`id`)
- UNIQUE (`name`)
```

### 规则

- **每张表一个 `###` 子标题**
- 必须写**一句话说明**表的用途
- 字段表格四列：字段名、类型、约束、说明
- 约束写清楚：主键、自增、非空、唯一、外键
- 新增字段标注 **待加** 或 **现有**
- 列出所有索引

## 4. ER 关系图画法

用文字版 ASCII 图，标注关系类型：

```
┌──────────┐     1:N     ┌──────────┐
│ 表A      │────────────>│ 表B      │
│          │             │          │
│ 关联字段  │             │ 关联字段  │
└──────────┘             └──────────┘
```

### 关系标注

| 符号 | 含义 |
|------|------|
| `1:N` | 一对多 |
| `N:1` | 多对一 |
| `M:N` | 多对多（通过中间表） |
| `1:1` | 一对一 |

## 5. 已知问题格式

```markdown
| 问题 | 影响 | 计划 |
|------|------|------|
| 缺少外键约束 | 数据一致性无保障 | 需求 001 排除，后续加 |
| 密码明文存储 | 安全风险 | 需求 001 排除，后续改哈希 |
```

### 规则

- 每个问题必须写**影响**和**计划**
- 计划要写清楚是「哪个需求做」还是「暂不处理」
- 已解决的问题移到变更记录，从已知问题删除

## 6. SQL 变更脚本格式

```markdown
## SQL 变更脚本

> 需求 001 执行时需要的 DDL，按顺序执行：

\`\`\`sql
-- 1. 说明这一步做什么
CREATE TABLE ...;

-- 2. 下一步
ALTER TABLE ...;
\`\`\`
```

### 规则

- 每步加**注释说明**做什么
- 按**执行顺序**编号
- 可复制直接执行
- 包含回滚说明（如果需要）

## 7. 命名规范

### 表名

- 全小写，复数形式：`students`、`scores`、`classes`
- 多词用下划线：`teacher_class`

### 字段名

- 全小写，下划线分隔：`student_id`、`class_name`
- 主键：`id` 或 `表名单数_id`（如 `teacher_id`）
- 外键：与关联表主键同名

### 索引名

- 普通索引：`idx_表名_字段名`
- 唯一索引：`uk_表名_字段名`

## 8. AI 使用规则

AI 在涉及数据库操作时，必须：

1. **先读 `docs/db-design.md`** — 确认当前表结构
2. **改结构前先改文档** — 更新设计文档，再写 SQL
3. **检查已知问题** — 避免重复踩坑
4. **SQL 脚本要能直接跑** — 不要写伪代码

## 9. 数据库备份规范

### 备份规则

- **每次修改数据库结构前**，必须先用 `mysqldump` 全量备份
- **每日定时备份**，保留最近 7 天的备份

### 备份命令

```bash
export MYSQL_PWD=<DB_PASSWORD>
mysqldump -u root student_db > db/backup_$(date +%Y%m%d).sql
```

### 备份文件位置

- 存放在 `db/` 目录下
- 命名格式：`backup_YYYYMMDD.sql`
- 重要操作前加备注：`backup_YYYYMMDD_before_XXXXX.sql`

### 变更数据库流程

1. 备份：`mysqldump -u root student_db > db/backup_YYYYMMDD_before_XXX.sql`
2. 执行 SQL 变更
3. 验证数据正确
4. 更新 `docs/db-design.md` 和 `docs/requirements/` 对应文档
5. 更新变更记录
